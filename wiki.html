Overview

Lilly AI runs on your Android phone via Termux with a Docker backend. It has:

  • 9 avatar agents — each with distinct personality and strengths
  • 23 phone sensors — light, accelerometer, gyroscope, GPS, battery, etc.
  • Natural language automation — "when X happens, do Y"
  • Notification intelligence — reads and prioritizes Android notifications
  • Voice interaction — speak to Lilly, she speaks back
  • Camera vision — YOLOv8 object detection from phone camera or browser webcam
  • Picture-in-Picture — YouTube while chatting

📷 Camera & Vision (YOLO)

Lilly can see through your phone camera or browser webcam using YOLOv8 object detection.

How It Works

Camera frames are sent to the backend every 2-3 seconds. YOLOv8 detects 80+ object classes (person, laptop, phone, cup, chair, car, etc.) and returns bounding boxes + labels.

Android Native Camera

The overlay camera captures frames from the phone's camera and POSTs them to POST /api/vision/browser. Detection boxes are drawn on the camera overlay in real-time.

Browser Webcam

The web UI's CameraBridge captures webcam frames via getUserMedia and sends them to the same endpoint. Detection results appear in the UI.

⚡ Natural Language Automation

Create rules by talking to Lilly:

Examples

"When battery is below 20%, notify me"

"When I get a Slack message about deploy, alert me"

"When light drops below 10, turn on dark mode"

"When I arrive home, set phone to silent"

Rule Structure

{
  "topic": "battery",        // sensor, battery, notification, location
  "condition": {
    "field": "data.battery_level",
    "op": "<",
    "value": 20
  },
  "action_type": "notify",   // notify, chat, shell, webhook, tts
  "action_payload": {
    "title": "Low Battery",
    "body": "Battery is at {{data.battery_level}}%"
  }
}

🔗 Pairing

Pair your phone with the web UI:

  1. Open the Lilly overlay on your phone
  2. Double-tap the head → tap Config ⚙️
  3. Tap "Re-pair Device"
  4. Enter the 6-digit code shown on the web UI

Once paired, the web UI sees your phone's sensors, notifications, and battery in real-time.

📡 Bluetooth Broadcast (Earbuds Mode)

Your Pixel 10 can advertise itself as a Bluetooth LE device — like earbuds in pairing mode. When nearby, it will appear in Bluetooth scans with your chosen avatar name and image.

How It Works

  1. Open the Lilly web UI on your host machine
  2. Click the hamburger menu ☰ → Broadcast button
  3. Choose an avatar image (🐶 Puppy, 🦊 Fox, 🐱 Cat, etc.)
  4. Set a device name (e.g., "Lilly Pup")
  5. Click "Start Broadcast" — your phone now appears in Bluetooth scans

Nearby phones will see your device appear as a discoverable BLE peripheral. They can open the broadcast web URL to see your avatar image — just like earbuds showing a pairing prompt.

Permissions Required (Android 12+)

On your Pixel 10, grant these permissions to Termux:

  • Location — Allow all the time (required for BLE advertising)
  • Nearby devices — Allow (Android 12+ Bluetooth permission)
  • Bluetooth — Allow

Also enable Location services: Settings → Location → High accuracy

📡 Container-Side Broadcast (No Phone Required)

Starting a broadcast directly from the Docker container — no phone needed. Uses ble_advertiser_host.py which talks to the host Bluetooth adapter via raw HCI commands (hcitool/hciconfig). This is the container equivalent of the Bluetooth LE Spam APK, using your own payloads (name, service UUID, image URL) — no third-party fake-device payloads.

  1. Ensure the host machine has a Bluetooth adapter and BlueZ is installed
  2. The container (via start.sh) auto-starts ble_advertiser_host.py on port 8110
  3. Broadcast from the API: 
    curl -X POST http://localhost:8098/api/bluetooth/advertise \
  -H "Content-Type: application/json" \
  -d '{"name":"Lilly Pup","mode":"balanced","image":"/static/lilly/puppy-avatar.svg"}'
  4. Check status: curl http://localhost:8098/api/bluetooth/advertise/status
  5. Stop broadcast: curl -X POST http://localhost:8098/api/bluetooth/advertise/stop
  6. Scan for nearby BLE devices: curl http://localhost:8098/api/bluetooth/advertise/scan
  7. Or just say: “broadcast” / “advertise” / “beacon”
ModeDescription
bleBLE advertising only (silent radar presence)
classicClassic BR/EDR headphone-pairing popup on nearby phones
fast_pairGoogle Fast Pair BLE — Android bottom-sheet popup
both / balancedClassic + Fast Pair BLE simultaneously (default, best coverage)

ℹ The container advertiser is tried first by _bt_proxy (always-local, no phone dependency). If no Bluetooth adapter is available, the phone-side advertiser (sensor server :8099 or standalone :8100) is used as a fallback. Download ble_advertiser_host.py to run standalone.
